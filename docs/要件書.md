# 段階式目覚ましアプリ 要件書

2026-10-07

## 1. 概要

本書は、iPhone の Scriptable とショートカットで作る「段階式目覚まし」の要件を、実装を担当する別のAIに引き渡すためのものである。音で段階的に起こし、起床チェックインが終わるまで次の段階のアラームを残すことで、二度寝を防ぐ。

| 項目 | 内容 |
| --- | --- |
| 目的 | 朝起きられない問題を解決し、起床から出発までを支える |
| 利用者 | 開発者本人1名（公開しない） |
| 実装方式 | 既存のTodoアプリと同じく **Scriptable（JavaScript）**。アラーム音は iPhone 標準の **時計アプリ**、操作と自動実行は **ショートカット** が担う |
| 対象環境 | iPhone、iOS 26 以上。Mac や Xcode は使わない |
| 費用 | 0円（有料API・有料サービスは使わない）。NFCタグを使う場合のみ数百円 |
| 言語 | 画面・通知・ウィジェットはすべて日本語 |
| 関連 | 既存のTodoアプリ（Scriptable）のデータを読み込み、ロック画面に表示する。現状のTodoアプリはロック画面に表示できていないため、本件で確実に表示できるようにする |

優先度は **Must（必須）・Should（できれば）・Could（余裕があれば）** の3段階で示す。本書で「確認が必要」とした点は、実装前に利用者へ確認すること。

## 2. システム構成

アラーム音は時計アプリ、アラームのオン/オフと自動実行はショートカット、判断・記録・表示は Scriptable が担う。

| 担当 | 役割 |
| --- | --- |
| 時計アプリ | 段階ごとのアラーム。マナーモード中も鳴り、Apple Watch にも届く |
| ショートカット | アラームのオン/オフ、バーコードの読み取り、時刻やNFCでの自動実行 |
| Scriptable | 設定と記録の保存、判定、画面、通知、ロック画面ウィジェット |

1日の流れ（毎晩アラームをオンにし、チェックインでオフにする）：

```
① アラーム準備（毎日20:00 ショートカット）
   → ② 段階的に鳴る（時計アプリ 段階0〜3／止めても次の段階は待機）
   → ③ 起床チェックイン（バーコードで残りをオフ）
   → 成功で記録
   → ④ 出発カウントダウン（ロック画面ウィジェット）
   → ⑤ 昼間はTodo表示（ロック画面ウィジェット）
   → ⑥ 就寝リマインド（Scriptable の通知）
   → 翌日へ（①に戻る）
```

チェックインがなければ最終段階まで鳴り続け、成功するとロック画面は出発カウントダウンから Todo、就寝リマインドへと切り替わる。

## 4. 段階アラームと起床チェックイン（F-01〜F-03）

アラームは時計アプリに「1回限り」のアラームとして段階の数だけ登録し、毎晩オンにして、チェックインでオフにする。時刻の変更はショートカットからできない前提とし、時計アプリで手動で設定する。

### 4.1 段階の初期設定

起床時刻 7:00 の場合の例。ラベル名はショートカットがアラームを見分けるために使うので、この名前で統一する。

| 段階 | 時計アプリのラベル | 時刻 | 音（時計アプリで選ぶ） | スコア |
| --- | --- | --- | --- | --- |
| 0：そっと | 起床-段階0 | 6:50 | 静かな音 | 100 |
| 1：ふつう | 起床-段階1 | 7:00 | 普通の音 | 85 |
| 2：しっかり | 起床-段階2 | 7:03 | 大きく速い音 | 70 |
| 3：最終 | 起床-段階3 | 7:06 | 一番強い音 | 40 |

- 各アラームの **スヌーズはオフ** にする（スヌーズの代わりに次の段階が鳴る）
- 段階の数と時刻は利用者が変えられる。Scriptable 側の設定ファイルにも同じ時刻を記録し、表示や判定に使う
- チェックインが段階0より前なら「自力で起床」としてスコア100。正午までにチェックインがなければ「未チェックイン」としてスコア0

### 4.2 動作のルール

1. 就寝前のオートメーションが、翌日が起床日なら「起床-段階0〜3」をすべてオンにする。祝日・「明日だけオフ」・起床しない曜日ならオンにしない
2. ある段階のアラームを時計アプリで停止しても、次の段階はオンのまま残る
3. チェックインが成功したら、残っている段階のアラームをすべてオフにし、起床記録を保存する
4. チェックインしないままだと、最終段階まですべて鳴る

### 4.3 チェックインの方法

| 方法 | 内容 | 優先度 |
| --- | --- | --- |
| バーコード | ショートカット「QR/バーコードをスキャン」で読み、登録済みの値と一致すれば成功。洗面所の歯磨き粉などを使う | Must |
| NFCタグ | 洗面所に貼ったタグにかざすと、NFCオートメーションが同じ処理を実行する | Could |

- バーコードの値は設定画面で登録する（その場で一度スキャンして保存）
- 一致しない場合は「登録したコードと違います」と表示し、アラームはオフにしない
- 歩数によるチェックインは、ヘルスケアへの歩数の反映が遅れるため採用しない

### 4.4 起床記録に保存するもの

日付、チェックイン時刻、起きた段階（チェックイン時刻までに鳴った最後の段階）、スコア、チェックイン方法。詳細は「7. データ要件」。

## 5. 出発カウントダウンと朝のルーティン（F-04、F-09〜F-11）

チェックインから出発時刻まで、ロック画面に残り時間と次にやることを表示し続ける。残り時間は Scriptable のウィジェットのタイマー表示（WidgetDate の applyTimerStyle）を使い、更新を待たずに減らしていく。

### 5.1 出発時刻

- 曜日ごとに出発時刻を設定する（例：平日 7:45、土日はなし）
- 出発時刻がない日は、カウントダウンを出さずに昼間の表示にする
- 出発時刻を過ぎたら、ウィジェットは昼間の表示（Todo）に切り替える

### 5.2 朝のルーティン（F-09）

| 順番 | 項目（例） | 所要時間 |
| --- | --- | --- |
| 1 | カーテンを開ける | 1分 |
| 2 | 洗顔 | 5分 |
| 3 | 朝食 | 15分 |
| 4 | 着替え | 10分 |
| 5 | 歯磨き | 5分 |

- 項目と所要時間は利用者が編集できる
- ウィジェットをタップすると Scriptable のスクリプトが開き、今の項目を「完了」にして次に進める
- 全部終わったら「出発準備OK」と表示する

### 5.3 遅刻の警告（F-11）

- 「現在時刻 ＋ 残りの項目の所要時間の合計」が出発時刻を超えたら、ウィジェットに「⚠ 3分遅れ」のように表示する
- 判定はスクリプトの実行時とウィジェットの更新時に行う（常に監視はできない）

### 5.4 持ち物チェック（F-10）

- チェックイン時に、出発5分前の通知を予約する（本文に持ち物の一覧）
- 通知をタップするとチェックリストを開き、項目をタップして確認する
- 初期の持ち物：鍵、財布、定期、スマホ（編集可）

## 6. ロック画面ウィジェット（F-05、F-06）

1つの Scriptable スクリプトでロック画面の3種類すべてに対応し、時間帯によって表示を切り替える。アラームが動いていない昼間は Todo を表示し、ロック画面を一日中役立てる。

### 6.1 時間帯の定義

| 時間帯 | 始まり | 終わり |
| --- | --- | --- |
| 起床中 | 段階0の時刻 | チェックイン完了 |
| 朝 | チェックイン完了 | 出発時刻 |
| 昼間 | 出発時刻（出発がない日はチェックイン完了） | 18:00（設定で変更可） |
| 夜 | 18:00 | 就寝予定時刻の30分前 |
| 就寝前 | 就寝予定時刻の30分前 | 翌朝の段階0の時刻 |

### 6.2 表示内容

| 種類 | 起床中 | 朝 | 昼間 | 夜 | 就寝前 |
| --- | --- | --- | --- | --- | --- |
| 1行（時計の上） | ⏰ チェックインして | 🚪 出発まで 18:32 | ✅ Todo 残り3件 | 🌙 就寝まで 1:20 | ⏰ 明日 7:00 起床 |
| 長方形 | 今の段階と次の段階の時刻 | 出発カウントダウン＋次のルーティン＋遅刻警告 | 未完了のTodo 上位3件 | 就寝までの時間＋明日の最初の予定 | 明日の起床時刻・段階数・今寝た場合の睡眠時間 |
| 円形 | 段階の番号 | 出発までの残り（輪で表示） | 今朝のスコア | Todoの残り件数 | 今週の平均スコア |

### 6.3 Todo 表示の要件（F-06）

現状のTodoアプリはロック画面に表示できていないため、以下を必ず満たす。

- ロック画面用の種類（`config.widgetFamily` が `accessoryInline`・`accessoryRectangular`・`accessoryCircular`）ごとに描画を分ける
- ロック画面は単色で表示されるため、色に頼らず文字と記号で区別する
- 長方形は3行まで。長いTodo名は省略記号で切る
- Todoアプリのデータファイルを読み取り専用で開く（書き込まない）。ファイルがない、または読めないときは「Todoを読み込めません」と表示し、他の表示を壊さない
- Todoのデータの保存場所と形式は未確認。実装前に既存スクリプトを確認して合わせる

### 6.4 その他の要件

- ウィジェットのパラメータに `todo` などを指定すると、時間帯に関係なくその表示に固定できる
- 次の時間帯の切り替わり時刻を `refreshAfterDate` に設定する。実際の更新は iOS が決めるため、15〜30分程度遅れてもよい
- ウィジェットをタップすると、時間帯に合った画面（ルーティン、Todo一覧など）を開く

## 7. データ要件

データは iCloud Drive の Scriptable フォルダ内 `WakeApp/` に JSON で保存する（`FileManager.iCloud()`）。iCloud にあるので、機種変更時も引き継がれる。

| ファイル | 内容 | 更新のタイミング |
| --- | --- | --- |
| `config.json` | 段階・曜日ごとの起床と出発時刻・就寝時刻・ルーティン・持ち物・チェックインのコード・Todoファイルの場所 | 設定画面で変更したとき |
| `state.json` | その日の状態（アラームをオンにしたか、チェックイン済みか、ルーティンの進み具合、明日だけオフ） | 各処理の実行時 |
| `sessions.json` | 起床記録の履歴（1日1件） | チェックイン時、正午の未チェックイン判定時 |

```json
// config.json の例
{
  "stages": [
    {"index": 0, "name": "そっと", "clockLabel": "起床-段階0", "time": "06:50", "score": 100},
    {"index": 1, "name": "ふつう", "clockLabel": "起床-段階1", "time": "07:00", "score": 85},
    {"index": 2, "name": "しっかり", "clockLabel": "起床-段階2", "time": "07:03", "score": 70},
    {"index": 3, "name": "最終", "clockLabel": "起床-段階3", "time": "07:06", "score": 40}
  ],
  "days": {"mon": {"wake": true, "departure": "07:45"}, "sat": {"wake": false, "departure": null}},
  "bedtime": "23:30",
  "daytimeEnd": "18:00",
  "skipHolidays": true,
  "checkinCode": "4901234567894",
  "routine": [{"name": "洗顔", "minutes": 5}, {"name": "朝食", "minutes": 15}],
  "belongings": ["鍵", "財布", "定期", "スマホ"],
  "todoFile": "（既存Todoアプリに合わせて設定）"
}

// sessions.json の1件分の例
{"date": "2026-10-08", "checkinAt": "2026-10-08T07:04:12+09:00", "wokeStage": 2, "score": 70, "method": "barcode", "late": false}
```

- すべてのスクリプトは、ファイルを読む前に iCloud からのダウンロードを待つ（`downloadFileFromiCloud`）
- ファイルが壊れているときは、初期設定で動き、設定画面でそのことを知らせる
- 時刻は日本時間（Asia/Tokyo）で扱う

## 8. ショートカットとオートメーション

時計アプリの操作はショートカットしかできないため、判断は Scriptable、アラームのオン/オフはショートカットと役割を分ける。ショートカットは Scriptable を「スクリプトを実行」で呼び、結果（`Script.setShortcutOutput`）を見て分岐する。

### 8.1 ショートカット

| ID | 名前 | 動き | 優先度 |
| --- | --- | --- | --- |
| S-01 | アラーム準備 | Scriptable に「明日は起床日か」を聞き、起床日なら「起床-段階0〜3」をオンにする | Must |
| S-02 | 起床チェックイン | バーコードを読み、Scriptable で照合。成功なら段階のアラームをすべてオフにし、結果を表示 | Must |
| S-03 | 明日だけオフ | Scriptable に翌日を休みとして記録し、すでにオンなら段階のアラームをオフにする | Should |
| S-04 | 次の起床は | 次の起床時刻と段階数を読み上げる（Siri 用） | Should |
| S-05 | テストで鳴らす | 1分後に「起床-テスト」アラームを作る | Should |

### 8.2 個人用オートメーション（すべて「すぐに実行」）

| ID | きっかけ | 実行するもの | 優先度 |
| --- | --- | --- | --- |
| A-01 | 毎日 20:00 | S-01（アラーム準備）。あわせて Scriptable が就寝リマインドの通知を予約する | Must |
| A-02 | 毎日 12:00 | Scriptable の未チェックイン判定（記録をスコア0で保存） | Must |
| A-03 | 毎週日曜 21:00 | Scriptable の週の振り返り通知 | Should |
| A-04 | NFCタグ | S-02 と同じ処理（バーコードの読み取りは省略） | Could |
| A-05 | SNSアプリを開いたとき | 起床中なら警告を出してホーム画面に戻る | Could |

- A-01 の時刻は、就寝時刻より前であれば利用者が変えてよい
- Scriptable のスクリプトは、ショートカットから渡された文字列（`args.shortcutParameter`、例：`plan`・`checkin:4901234567894`・`noon`）で処理を切り替える
- ショートカットの作り方は、引き渡し先のAIが手順書として利用者に渡す（ショートカットはコードで配布できないため）

## 9. 非機能要件

最優先は「アラームが必ず鳴ること」であり、Scriptable やショートカットが失敗しても、鳴る側に倒れるように作る。

| 分類 | 要件 |
| --- | --- |
| 信頼性 | チェックイン処理が途中で失敗した場合、アラームはオンのまま残す（記録より起こすことを優先） |
| 信頼性 | A-01 が動かなかった日に備え、就寝リマインドの通知からも S-01 を実行できるようにする |
| 費用 | 有料のAPI・サービス・アプリを使わない。外部APIは無料・APIキー不要のもの（Open-Meteo）に限る |
| 動作速度 | ウィジェットの描画は通信なしで完了する（天気などは事前に保存した値を使う） |
| 保守性 | 共通処理は1つのモジュールにまとめ、`importModule` で読み込む |
| 保守性 | 設定値（時刻、ラベル名、スコア）はコードに直接書かず、config.json から読む |
| 使いやすさ | 画面は Scriptable の UITable と Alert で作る。寝ぼけていても使えるよう、朝の画面はボタンを大きく、文字数を少なくする |
| 使いやすさ | すべての表示を日本語にする |
| データ保護 | 記録は iCloud Drive にだけ保存し、外部に送信しない |

## 10. 制約・不採用・検証項目

時計アプリのアラームの時刻をショートカットから変えられないことが最大の制約であり、時刻を自動で動かす機能はすべて不採用とした。

### 10.1 不採用とした機能

| 機能 | 理由 |
| --- | --- |
| YouTube Music のアプリ内再生・連携 | 画面ロックで停止する、アプリ内ではログインできず広告が入る、再生履歴を取得できない |
| 段階の自動調整・早起きトレーニング | アラームの時刻をショートカットから変えられない |
| 天気に合わせた早起き | 同上 |
| 目を開けてチェックイン | Scriptable に顔を判定する機能がない |
| 歩数でチェックイン | ヘルスケアへの歩数の反映が遅れる |
| スクリーンタイムによるアプリのロック | Scriptable からは使えない（F-19 の警告で代用） |
| Apple Watch 専用の機能 | 時計アプリのアラームが Watch にも届くため不要 |
| スマートロック（SESAME 5）の状態表示 | ハブがなく、ネット経由で状態を取得できない |

### 10.2 実機で検証する項目

実装の前に確かめ、結果によって要件を見直す。

- [ ] ショートカット「アラームを切り替え」で、ラベル名を指定して特定のアラームをオン/オフできるか
- [ ] 1回限りのアラームが鳴った後、ショートカットから再びオンにでき、翌日の同じ時刻に鳴るか
- [ ] ショートカットでアラームの時刻を変更・削除できるか（できれば不採用の機能を復活できる）
- [ ] 時刻のオートメーションが、ロック中・低電力モード中でも確実に実行されるか
- [ ] 通話中（電話・LINE・FaceTime）に時計アプリのアラームがどう鳴るか
- [ ] ロック画面ウィジェットの更新間隔と、タイマー表示がロック画面で動き続けるか
- [ ] 既存Todoアプリのデータの保存場所と形式、ロック画面に表示できていない原因

## 11. 実装の進め方（引き渡し先AI向け）

検証項目を先に済ませ、「起こす → チェックイン → ロック画面」の順で、毎回実機で動かせる単位で作る。

1. **検証**：10.2 の項目を利用者と確かめる。特にアラームのオン/オフと、既存Todoアプリのデータ形式
2. **共通モジュール**：設定と記録の読み書き、日付と時間帯の判定、スコア計算（例：`WakeCore.js`）
3. **段階アラームとチェックイン**：F-01〜F-03、S-01、S-02、A-01、A-02。ショートカットの作成手順書もここで渡す
4. **ロック画面ウィジェット**：F-05、F-06。まず Todo の表示を確実に動かし、次に時間帯の切り替えを足す
5. **出発カウントダウンと就寝リマインド**：F-04、F-07
6. **Should の機能**：F-08〜F-16、S-03〜S-05、A-03
7. **Could の機能**：F-17〜F-20、A-04、A-05

### 注意点

- 成果物は Scriptable に貼り付けてそのまま動く JavaScript ファイルと、ショートカットの作成手順書（日本語）とする
- Scriptable の API にない機能を前提にしない。不明な点は推測で埋めず、利用者に確認する
- 既存Todoアプリのファイルは読むだけにし、形式を変えない
- 利用者はプログラミングの専門家ではないため、手順は画面のボタン名を使って具体的に書く
